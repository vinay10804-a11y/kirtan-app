# Sacinandana Swami and Gour Krishna Kirtans

Offline-capable web app (PWA) for kirtans, bhajans and guided japa, built for Vinay
(devotee name Vinoda Govinda; use that name when talking about this project).
Hosted on his Cloudflare account: a Worker serves `site/` and streams audio from the
R2 bucket `kirtans` at `/audio/*`.

## Layout
- `site/`: the app (plain HTML/CSS/JS, no framework). `app.js` renders hash routes into `#view`;
  `sw.js` caches the shell and serves saved audio offline; `catalog.json`, `videos.json` and
  `photos.json` are generated by the build.
- `worker/index.js`: serves `/audio/*` from R2 with Range support; everything else is a static asset.
- `tools/`: `build.mjs` (scan → compress → catalog), `classify.mjs` (sorting rules),
  `upload.mjs` (to R2), `fetch-japa.sh` + `videos.mjs` (YouTube/SoundCloud japa),
  `fetch-spotify.sh`, `photos.mjs`, `pull-source.mjs` (originals from R2 → `source/`).
- `publish.sh`: the full pipeline on a Mac.

## Decisions the owner has made (keep them)

  section; "Radhanath"/"Gopal" paths map to Gour Krishna). Anything else is skipped and listed.

- Japa (owner's choice, 19 Oct 2026): nothing is downloaded. Guided Japa are YouTube video cards
  (thumbnail opens YouTube) whose "Listen here" plays the YouTube video in place. Japa Inspirations
  (the SoundCloud set "japa-inspirations", owner's choice 22 Oct 2026) and Living Name Meditations are
  SoundCloud tracks, each row with its artwork, that open SoundCloud's player under the title.
  `tools/videos.mjs` writes the list to `site/videos.json`. Guided Japa videos are listed in
  `tools/guided-japa.txt`. If audio copies are ever added (Kirtans/Japa), "Listen here" uses them instead.
- Home: the wave image (`site/art/card-1.webp`), a one-line intro, Kirtans and Japa cards with short
  explanations and links, Recently added, "How to use this site". No quote section, no photo strip.
- No watercolour images as track artwork. Tracks use embedded cover art, else a plain initials tile.
- Design: clean, calm, easy to navigate, not clunky; cream/teal palette, EB Garamond + system UI.

  site login-only (Cloudflare Access) before publishing them.
- Quotes must be verified, never invented. Lyrics appear only on Bhajans: `site/lyrics.json` maps each
  bhajan to its kksongs.org page and verified author. The owner wants lyrics inside the app: the lyrics
  card opens the kksongs.org page in an in-app panel (an iframe). Words and translations in the app's own
  style (`verses`) must come from the owner or a source we may use; never copy them from websites or
  write them from memory.
- Swipe the player artwork or mini player left/right to change recordings; swipe down on the player's
  top bar to close it. The progress bar works like Spotify's (tap to jump, drag, seek on release).
- Spotify-inspired (22 Oct 2026): every kirtan has a "⋯" menu (Play next, Add to queue, Add to playlist,
  Favourite, Save offline, Share; inside a playlist also Move up/down and Remove). "Up next" in the
  player opens the queue. Library tabs: Favourites, Playlists, Saved offline, History. Playlists live in
  the browser's storage on each device (no accounts).
- Appearance: Automatic (follows the device), Light or Dark, in Library and as a sun/moon button
  (home top bar on phones, side menu on laptops). Stored as `kk.theme`; an inline script in index.html

- Home has a "Use it as an app" section with install steps for iPhone and laptop, Safari and Chrome

- `NOTES.md` is the owner's running list of changes still to make and what is needed from them.

## First run on the owner's Mac (the chosen path)
The owner is not technical: explain in plain English, one step at a time, and do the work yourself.
1. Everything lives in `~/Desktop/sns kirtan platform/`: the recordings folder (expected name `Kirtans`;
   check the real name), the `photos of sns` folder, and this project as `kirtan-app`. The scripts default
   to a `Kirtans` folder beside the project; pass the path explicitly if it's named differently.
2. Install what's missing with Homebrew (`node ffmpeg yt-dlp`, plus `pipx install spotdl`).
3. Run `node tools/build.mjs` and show the owner the category summary and the skipped list. Fix
   `tools/classify.mjs` until every kirtan sits under the right artist, type, year and place.
4. Ask which photos are Gour Krishna and which are Sacinandana Swami; rename them so `tools/photos.mjs`
   tags them (names containing "gour" or "sns").
5. Run `./publish.sh` (add `--download` only to download Japa/Spotify audio). `wrangler login` opens a browser for the owner to click Allow; no API keys are
   needed on the Mac. If YouTube or Spotify downloads fail, debug them (spotdl may need the owner's own
   Spotify client ID/secret).
6. Give the owner the live link, and remind them about Add to Home Screen on their phone.

## What's online, and the owner's Mac (since 19 Oct 2026)
`site/catalog.json` (in git) is the record of what's online. The build keeps every catalog entry even
when its original isn't on the Mac, re-applies `classify.mjs` to it (each entry stores `rel`, its path
in the Kirtans folder), and only compresses files that are new. So the owner may delete originals and
`build/` once published, and the Kirtans folder only needs new recordings until they're published.
`--forget-missing` (build or publish) drops entries whose original is gone; use it only when the owner
wants recordings removed. Cover art lives in `site/covers/` (in git).

Sorting/place changes with no recordings to hand: `node tools/build.mjs none && npx wrangler deploy`.

Audio format (owner's choice, 19 Oct 2026): AAC 96 kbps stereo in .m4a, made with Apple's encoder
(`aac_at`), under `media/` in the `kirtans` bucket (FORMAT `aac96` in build.mjs; files at or below
100 kbps are copied as-is). Total about 3.5 GB, inside R2's free 10 GB; keep it there. The old 128k
MP3s under `audio/` are no longer used. The owner chose not to keep a backup of the originals on
Cloudflare: the published files are the only copy once local files are deleted, so a future format
change can only re-encode files whose originals are on the Mac (others are kept as they are).

## Working in the cloud (no Mac)
There are no originals in the cloud (the `kirtans-source` backup was removed at the owner's request;
`tools/pull-source.mjs` only matters if it's ever recreated). Sorting changes need no recordings.
With `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` set, Wrangler deploys and uploads non-interactively.

For sorting changes, or new recordings in a folder of their own:
```
npm install
node tools/build.mjs <folder with only the new recordings, or "none">   # prints the category summary
node tools/upload.mjs                 # new compressed audio → R2 bucket "kirtans"
npx wrangler deploy
```
Show the owner the category summary before deploying. YouTube downloads often fail from cloud IPs;
if `tools/fetch-japa.sh` is blocked, give the owner the Mac commands instead.

## Offline start (fixed 22 Oct 2026)
The app must open with no signal (e.g. on the Underground). `sw.js` opens pages network-first with a
3-second timeout, falling back to the cached `./`; never cache or serve `index.html` (Cloudflare
redirects it to `/`, and Safari refuses redirected responses for page loads, which stopped the app
opening offline). Data JSON falls back to cache after 4 seconds. EB Garamond is self-hosted in
`site/fonts/` (OFL) and pre-cached, so nothing render-blocking comes from another site. On iPhone the
home-screen app has its own storage, separate from Safari: kirtans must be saved from inside it.
